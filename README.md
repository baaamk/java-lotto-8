# java-lotto-precourse

# 기능 요구 사항

간단한 로또 발매기를 구현한다.

- 로또 번호의 숫자 범위는 1~45까지이다. 
- 1개의 로또를 발행할 때 중복되지 않는 6개의 숫자를 뽑는다.
- 당첨 번호 추첨 시 중복되지 않는 숫자 6개와 보너스 번호 1개를 뽑는다.
- 당첨은 1등부터 5등까지 있다. 당첨 기준과 금액은 아래와 같다.
  - 1등: 6개 번호 일치 / 2,000,000,000원
  - 2등: 5개 번호 + 보너스 번호 일치 / 30,000,000원
  - 3등: 5개 번호 일치 / 1,500,000원
  - 4등: 4개 번호 일치 / 50,000원
  - 5등: 3개 번호 일치 / 5,000원
- 로또 구입 금액을 입력하면 구입 금액에 해당하는 만큼 로또를 발행해야 한다.
- 로또 1장의 가격은 1,000원이다.
- 당첨 번호와 보너스 번호를 입력받는다.
- 사용자가 구매한 로또 번호와 당첨 번호를 비교하여 당첨 내역 및 수익률을 출력하고 로또 게임을 종료한다.
- 사용자가 잘못된 값을 입력할 경우 IllegalArgumentException을 발생시키고, "[ERROR]"로 시작하는 에러 메시지를 출력 후 그 부분부터 입력을 다시 받는다.
  - Exception이 아닌 IllegalArgumentException, IllegalStateException 등과 같은 명확한 유형을 처리한다.

## 입출력 요구사항
### 입력
- 로또 구입 금액을 입력 받는다. 구입 금액은 1,000원 단위로 입력 받으며 1,000원으로 나누어 떨어지지 않는 경우 예외 처리한다.
```
14000
```
- 당첨 번호를 입력 받는다. 번호는 쉼표(,)를 기준으로 구분한다.
```
1,2,3,4,5,6
```
- 보너스 번호를 입력 받는다.
```
7
```

### 출력
- 발행한 로또 수량 및 번호를 출력한다. 로또 번호는 오름차순으로 정렬하여 보여준다.
```
8개를 구매했습니다.
[8, 21, 23, 41, 42, 43]
[3, 5, 11, 16, 32, 38]
[7, 11, 16, 35, 36, 44]
[1, 8, 11, 31, 41, 42]
[13, 14, 16, 38, 42, 45]
[7, 11, 30, 40, 42, 43]
[2, 13, 22, 32, 38, 45]
[1, 3, 5, 14, 22, 45]
```

- 당첨 내역을 출력한다.
```
3개 일치 (5,000원) - 1개
4개 일치 (50,000원) - 0개
5개 일치 (1,500,000원) - 0개
5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
6개 일치 (2,000,000,000원) - 0개
```
- 수익률은 소수점 둘째 자리에서 반올림한다. (ex. 100.0%, 51.5%, 1,000,000.0%)
```
총 수익률은 62.5%입니다.
```

- 예외 상황 시 에러 문구를 출력해야 한다. 단, 에러 문구는 "[ERROR]"로 시작해야 한다.
```
[ERROR] 로또 번호는 1부터 45 사이의 숫자여야 합니다.
```

# 요구사항 정의
## 기능
- [x] 구입 금액을 입력받는다.
- [x] 당첨 번호를 입력 받는다.
- [x] 보너스 번호를 입력받는다.
- [x] 구매 개수와 구매 로또를 출력한다.
- [x] 당첨 통계를 출력한다.

## 처리
- [x] 구입금액
  - [x] 구입금액은 1,000원 단위로 입력받는다
  - [x] 최대 구입금액은 100,000원이다.
  - [x] 구입 금액은 1,000원 이상의 양의 정수로 입력 받는다.
  - [x] 오직 숫자만 입력한다.
-[x] 당첨 번호
  - [x] 쉼표로 구분한다.
  - [x] 입력 범위는 1~45로 정수로 입력받는다.
  - [x] 오직 숫자만 입력한다.
  - [x] 중복되지 않는 번호로 입력받는다.
-[x] 보너스 번호
  - [x] 입력 범위는 1~45로 정수로 입력받는다.
  - [x] 당첨 번호와 중복되어선 안된다.
  - [x] 오직 숫자만 입력한다.
-[x] 구매개수
  - [x] 구입금액/1,000 을 계산한 값이다.
-[x] 구매 로또
  - [x] 대괄호 안에 번호를 출력한다.
  - [x] 오름차순으로 정렬한다.
  - [x] 번호 1~45 번호로 무작위 생성된다.
  - [x] 한 행에 한 줄로 출력한다.
-[ ] 당첨 통계
  - [x] 구매로또와 당첨번호의 일치 개수를 출력한다.
  - [x] 5개 일치와 5개 + 보너스볼 일치를 구분한다.
  - [x] 총 수익률은 (당첨금액/ 구입금액)*100 으로 구한다.
  - [x] 총 수익률은 소수점 둘째자리에서 반올림한다.

## 예외
- [ ] 사용자가 잘못된 값을 입력할 경우 IllegalArgumentException을 발생시키고, "[ERROR]"로 시작하는 에러 메시지를 출력 후 그 부분부터 입력을 다시 받는다.
- [ ] Exception이 아닌 IllegalArgumentException, IllegalStateException 등과 같은 명확한 유형을 처리한다.
- [x] IllegalArgumentException = 전달된 인자가 유효하지 않은 경우.
  - [x] 구입 금액을 1,000원 단위로 입력하지 않은 경우
  - [x] 구입 금액을 1,000원 이하로 입력하는 경우
  - [x] 최대 구입금액보다 많이 입력한 경우
  - [x] 구입 금액에 숫자 이외의 값이 있을 경우
  - [x] 당첨 번호를 1~45 이내의 숫자로 입력하지 않았을 경우
  - [x] 당첨 번호 구분자가 잘못되었을 경우
  - [x] 당첨 번호 구분자 사이에 번호가 없거나 구분자로 시작 또는 끝나는 경우.
  - [x] 당첨 번호를 자연수로 입력하지 않았을 경우
  - [x] 당첨 번호에 중복된 번호가 있을 경우
  - [x] 당첨 번호를 6개 입력하지 않은 경우.
  - [x] 보너스 번호가 당첨번호와 중복될 경우
  - [x] 보너스 번호를 1~45 이내의 숫자로 입력하지 않았을 경우
  - [x] 보너스 번호를 자연수로 입력하지 않았을 경우
- [ ] IllegalStateException - 대상 객체의 상태가 호출된 메서드를 수행하기에 적절하지 않을 때
  - [ ] 구입 금액을 입력하지 않았는데 구입 하위 메서드가 호출 되었을 때
  - [ ] 구입 금액을 입력했는데 다시 호출될 때
  - [ ] 당첨 번호를 입력하지 않았는데 당첨번호 입력 하위 메서드가 호출 되었을 때
  - [ ] 당첨 번호를 입력 했는데, 해당 또는 상위 메서드가 다시 호출될 때
  - [ ] 보너스 번호를 입력하지 않았는데 보너스 번호 하위 메서드가 호출되었을 때
  - [ ] 보너스 번호를 입력했는데 해당 또는 상위 메서드가 다시 호출될 때
  - [ ] 당첨 통계 메서드가 수행 되었는데 상위 메서드 또는 해당 메서드가 다시 호출될 때
- [ ] NullPointerException - 인자가 null 일때
  - [ ] 구입금액이 null일 때
  - [ ] 당첨번호 자체가 null일 때
  - [ ] 개별 당첨 번호가 null일 때
  - [ ] 당첨 금액이 null일 때
  - [ ] 구매 로또가 null일 때
  - [ ] 구매 개수가 null일 때
  - [ ] 보너스 번호가 null일 때
  - [ ] 수익률이 null일 때

# 설계 방향
1. @FunctionalInterface을 사용한 InputRetryHandler 함수를 만들어 공통 관리 한다.
   2. 한 컨트롤러 내에서 진행되기 때문에 컨트롤러 내부 메서드로만 구현
2. getter을 최대한 쓰지 않는다. 단, dto사용은 예외한다.
3. 원시값을 래핑한 클래스를 생성한다.
4. Enum을 적용하며 이것도 객체이기 때문에 안에 메서드를 구현한다.
5. Controller의 과도한 책임을 ServiceLayer에 분리한다. 단, 이때도 하나의 서비스만 시행한다.
6. toString도 view로 가면 안되기 때문에 dto에서만 구현한다.
7. dto는 Recode로 사용하려 노력한다.
8. 보너스 넘버는 같은 로직이기 때문에 로또 넘버를 감싼다.
